# Migrate from 3.21.1 to 3.22.1

## New features

### Project-owned instances

`bytebase_instance`, `data.bytebase_instance`, and `data.bytebase_instance_list` now accept an optional `parent` in `projects/{project}` format. Set it to create or query project-owned instances; omit it for workspace-owned instances. Changing a managed instance's `parent` replaces the instance.

Project-owned instances use the full name `projects/{project}/instances/{instance}`. The resource and both data sources use the same parent:

```terraform
resource "bytebase_instance" "project_postgres" {
  parent      = "projects/example"
  resource_id = "project-postgres"
  title       = "Project PostgreSQL"
  engine      = "POSTGRES"
  environment = "environments/test"

  data_sources {
    id       = "admin"
    type     = "ADMIN"
    host     = "postgres.example.com"
    port     = "5432"
    username = "bytebase"
  }
}

data "bytebase_instance" "project_postgres" {
  parent      = "projects/example"
  resource_id = bytebase_instance.project_postgres.resource_id
}

data "bytebase_instance_list" "project" {
  parent = "projects/example"
}
```

Use the full project-owned instance name when importing:

```bash
terraform import bytebase_instance.project_postgres projects/example/instances/project-postgres
```

## Behavior changes

### Webhook URLs are write-only

Bytebase no longer returns saved project webhook URLs. Like other write-only passwords in the provider, the `bytebase_project` resource preserves the configured URL in Terraform state so unchanged webhooks continue to converge. Project data sources return an empty `webhooks.url` because the server does not expose the secret.

The URL remains marked sensitive in Terraform output, but the configured value is present in resource state. Protect remote or local state with the same controls used for other managed passwords.

State written by a digest-based provider version may show a one-time webhook URL update after upgrading. Apply it once to migrate the stored value; subsequent unchanged plans converge.

## Breaking changes

### CockroachDB `cluster` removed

The Bytebase API no longer exposes `DataSource.cluster`, so `bytebase_instance.data_sources.cluster` has been removed. Delete this argument from Terraform configurations before upgrading. Existing state will discard the field during refresh; no manual state migration is required.

### `bytebase_user.service_key` removed

The Bytebase API no longer exposes `service_key` on the `User` type. The computed `bytebase_user.service_key` attribute has therefore been removed. Service-account keys belong to the separate `bytebase_service_account` resource and remain write-only.
